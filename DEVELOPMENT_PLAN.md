# FaceLock — Development & Architectural Evolution Plan

## 1. Project Overview & Current Architecture

**FaceLock** is an AI-powered facial authentication and secure credential recovery system that uses deep facial embeddings (128-dimensional vectors from `dlib` / `face_recognition`) to authenticate users in real-time via live webcam streams.

### Current Directory Structure
```
Face Recognition and Password-Reset System/
├── active_password.npy       # Stored reference face embedding (NumPy 128-d vector)
├── main.py                   # OpenCV webcam loop & HUD interface
├── requirements.txt          # Pinned runtime and testing dependencies
├── core/
│   ├── __init__.py
│   ├── embedding.py          # BGR->RGB conversion & 128-D vector extraction
│   ├── matcher.py            # Euclidean distance matcher (L2 norm <= 0.6)
│   └── persistence.py        # Atomic disk persistence & path safety validation
├── utils/
│   ├── __init__.py
│   └── camera.py             # WebcamManager with context manager lifecycle
├── workflows/
│   ├── __init__.py
│   ├── register.py           # Single-frame face password registration/reset
│   └── authenticate.py       # Live candidate face authentication workflow
└── tests/
    ├── __init__.py
    └── test_evaluator.py     # 6 hardware-isolated synthetic unit/integration tests
```

## 2. Current Functionality & Execution Flow

```
Webcam (WebcamManager) 
    │
    ▼
Live BGR Frame ──► main.py (OpenCV HUD Loop)
                     │
     ┌───────────────┴───────────────┐
     │ [r] Register/Reset            │ [a] Authenticate
     ▼                               ▼
workflows/register.py          workflows/authenticate.py
     │                               │
     ├─► core/embedding.py           ├─► core/persistence.py (load active)
     │   (128-D vector)              ├─► core/embedding.py (live vector)
     ▼                               ▼
core/persistence.py            core/matcher.py (Euclidean norm <= 0.6)
     │ (atomic tmp save)             │
     ▼                               ▼
active_password.npy            Access Granted / Denied Banner (HUD)
```

1. **`main.py`**: Runs the OpenCV capture loop, renders HUD status (Password: SET/NOT SET), captures hotkeys (`[a]`, `[r]`, `[q]`), and displays transient result banners.
2. **`core/embedding.py`**: Detects face locations and computes 128-D embeddings using dlib's ResNet face encoder.
3. **`core/matcher.py`**: Compares candidate and stored embeddings with Euclidean distance $d = \|\mathbf{u} - \mathbf{v}\|_2$ against default threshold `0.6`.
4. **`core/persistence.py`**: Atomically saves and loads 128-D arrays to disk via `.tmp.npy` file replacement and directory path verification.
5. **`workflows/`**: Handles business logic for registering credentials and evaluating live authentication requests.
6. **`utils/camera.py`**: Guarantees hardware release via context manager protocols (`__enter__` / `__exit__`).
7. **`tests/test_evaluator.py`**: 6/6 tests passing in isolated environment with synthetic embeddings.

## 3. What Must NOT Be Changed (Invariants)

To preserve system reliability and backward compatibility:
- **Embedding model & dimension**: 128-dimensional embeddings generated by `face_recognition` / `dlib`.
- **Core matching baseline**: `compare_embeddings()` returning `(is_match, distance)` using L2 norm.
- **Webcam lifecycle contract**: `WebcamManager` context manager protocol ensuring leak-free hardware release.
- **Persistence safety invariants**: Atomic file operations (`os.replace`) and base directory validation.
- **Existing test baseline**: `tests/test_evaluator.py` must remain 100% passing at all stages.

## 4. Identified Gaps & Architectural Risks

| Risk / Gap | Impact | Proposed Mitigation |
| :--- | :--- | :--- |
| **Presentation Attack Vulnerability** | 2D photos or screens can bypass auth. | Add anti-spoofing / liveness detection (EAR blink detection & motion cues). |
| **Single-frame Fluctuation** | Blinks or bad lighting during `[r]` can save poor embeddings. | Implement multi-frame registration with outlier rejection and vector averaging. |
| **Single-user Constraint** | Hardcoded to one `active_password.npy`. | Add multi-user credential store while preserving single-user default fallback. |
| **Biometrics in Plaintext** | Raw NumPy array stored without encryption. | Integrate cryptographic encryption/hashing at rest (AES / Fernet). |
| **Lack of Quantitative Benchmark** | Threshold 0.6 not empirically benchmarked for FAR/FRR. | Add offline evaluation engine computing ROC curves, FAR, FRR, and EER. |
| **No Audit Trail** | Security events only output to console. | Add structured audit logging (JSON / SQLite) for compliance and forensic analysis. |

## 6. Safe Integration Points

1. **`core/liveness.py`**: Intercepts frame stream before `workflows/authenticate.py` to verify human presence.
2. **`workflows/register.py`**: Add `register_multiframe_face_password(camera, frames=5)` without breaking `register_face_password(frame)`.
3. **`core/persistence.py`**: Add user-parameterized methods `save_user_password(user_id, ...)` and `load_user_password(user_id, ...)` while keeping `save_active_password` as default alias.
4. **`core/security.py`**: Hook into `save_active_password` / `load_active_password` as an optional transparent encryption layer.
5. **`main.py`**: Enhance HUD with dynamic overlays (face bounding box tracking, liveness challenge indicator, progress bars).

## 7. Recommended Phased Implementation Order

1. **Phase 1: Multi-frame Registration & Vector Averaging** (`core/embedding.py` helper + `workflows/register.py`)
2. **Phase 2: Liveness & Anti-Spoofing Engine** (`core/liveness.py` + integration into `workflows/authenticate.py`)
3. **Phase 3: Secure Biometric Storage & Audit Logging** (`core/security.py` + `utils/audit_logger.py`)
4. **Phase 4: Multi-User Profile Management** (Extending `core/persistence.py` & user selection in `main.py`)
5. **Phase 5: Evaluation Engine (FAR/FRR/ROC/Confusion Matrix)** (`core/metrics.py` + `evaluation/`)
6. **Phase 6: Enhanced HUD & Visualization Polish** (`main.py` UI upgrade + `utils/visualizer.py`)
7. **Phase 7: Comprehensive Test Suite & Documentation** (Unit tests for all modules + updated README & docs)

## 8. Testing Strategy

- **Regression Testing**: Execute `.\.venv\Scripts\pytest.exe -v` after each module addition to ensure 0 regression on `test_evaluator.py`.
- **Synthetic Unit Testing**: Create dedicated synthetic tests for math/metrics (`test_metrics.py`), encryption (`test_security.py`), and frame aggregation (`test_multiframe.py`) without requiring live camera hardware.
- **Mocked Workflow Testing**: Mock `dlib` facial landmarks and eye aspect ratios to test liveness state machines deterministically.
